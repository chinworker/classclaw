你是一名资深产品设计师、前端架构师和 Web 工程师。请在现有 ClassClaw 仓库中实现一套可直接运行、面向管理员和班主任的完整网页应用。

这不是静态演示、设计稿或 localStorage 原型。网页必须连接仓库中已经实现的 FastAPI 后端，真实完成登录、查询、文件上传、预览、确认、智能体绑定和管理员调试等流程。

## 一、目标与交付

实现一个完整的 ClassClaw Web 工作台，至少包括：

1. 登录与账户中心。
2. 管理员工作台。
3. 班主任工作台。
4. 首次班级 onboarding。
5. 班级、学生和学生详情。
6. 带“讲台面向座位”空间感的可编辑座位表，以及“周一至周五 × 节次”的可编辑课表。
7. 值日、作业、考勤、表现、考试成绩和调课。
8. 面向班主任真实问题的快捷查询中心，例如今日未交、某科未交、前天课堂睡觉、某生近期表现。

11. OpenClaw 状态、班级智能体和微信二维码绑定。

## 二、技术约束

- 使用原生 HTML、CSS、现代 JavaScript 和 ES Modules。
- 不使用 React、Vue、Angular、jQuery 或大型 UI 框架。
- 不依赖 Node 构建、CDN、远程字体或网络图标库。
- 页面由 FastAPI `StaticFiles` 直接提供，启动后即可使用。
- 业务数据全部来自 `/api/v1`，禁止用 localStorage 模拟 CRUD。
- `sessionStorage` 只允许保存登录令牌、当前页和纯 UI 偏好；不能保存班级业务数据或密码。
- 所有日期显示按 `Asia/Shanghai`，请求日期使用 `YYYY-MM-DD`，日期时间使用 ISO 8601。
- 所有动态文本必须安全插入 DOM；使用 `textContent` 或统一 `escapeHtml()`，禁止 XSS。
- 所有录入使用页面内 Modal、Drawer 或独立表单，禁止使用浏览器原生 `prompt()`。
- 所有危险操作必须有明确二次确认，不使用模糊的“确定吗”。
- 桌面端和移动端都必须可用，至少适配 375px、768px、1024px 和宽屏。
- 不修改后端业务语义，不添加绕过确认的前端捷径。

## 三、真实认证与权限

API 前缀：

```text
/api/v1
```

登录：

```http
POST /api/v1/auth/login
Content-Type: application/json

{
  "username": "admin",
  "password": "32767"
}
```

登录后只保存 `access_token`，所有受保护请求统一发送：

```http
Authorization: Bearer <access_token>
X-ClassClaw-Surface: web
```

必须实现：

- `POST /auth/login`
- `GET /auth/me`
- `POST /auth/change-password`
- `POST /auth/logout`

权限规则：

- 系统最多一个管理员，默认用户名 `admin`，初始密码 `32767`。
- 普通用户角色固定为 `head_teacher`。
- 账号只能由管理员创建；登录页、班主任工作台和 onboarding 均不得出现“注册账号”或“自行创建账号”。
- 管理员可管理用户、查看所有班级、管理智能体、查看只读数据库调试信息。
- 每个班主任账号在任意时刻最多拥有一个未删除班级。`GET /auth/me` 或 `GET /classes` 返回已有班级时，登录后直接进入该班工作台，不出现班级选择器，也不显示“再创建班级”。
- 班主任没有班级时进入空班级欢迎页，只显示“创建班级”主按钮和可恢复的 onboarding；不要显示空业务仪表盘。
- 班级彻底删除成功后，当前账号恢复为“无班级”状态，可以重新创建一个班级。前端必须清空内存中的 class_id、班级缓存和旧业务路由，再重新请求 `/auth/me` 与 `/classes`。
- 管理员本身不受“必须拥有一个班级”约束，但不能用管理员页面替普通用户绕开“一账号一班级”的唯一性。
- `must_change_password=true` 时，在顶栏和账户页持续展示醒目提醒，并提供修改密码入口；不要强制跳转到无法退出的死循环。
- 收到 401：清除会话并返回登录页，说明“登录已过期”。
- 收到 403：展示权限不足，不隐藏后端错误详情中的必要上下文。
- 管理员菜单不能出现在班主任侧边栏中；即使通过 URL 进入也必须由后端再次拒绝。

禁止在代码中硬编码真实 API Token、Gateway Token 或用户密码。

### 账号与班级状态机

前端必须以重新获取的 `/auth/me.class_id` 和班级接口结果为事实来源，不根据旧页面、localStorage 或“曾经创建过”自行推断：

| 当前状态 | 登录后入口 | 允许的主操作 | 禁止行为 |
|---|---|---|---|
| 班主任、`class_id` 有值 | 直接进入该班工作台 | 查看和维护唯一班级 | 班级选择器、创建第二个班级 |
| 班主任、`class_id` 为空、有未完成 onboarding | 无班级欢迎页 | 继续草稿或放弃草稿后新建 | 展示旧班级业务数据 |
| 班主任、`class_id` 为空、无草稿 | 无班级欢迎页 | 创建班级 | 进入空壳业务工作台 |
| 彻底删除请求处理中或失败 | 保持当前班级上下文 | 查看错误、重试或取消 | 提前清除界面、把停用当删除 |
| 彻底删除成功 | 清空班级缓存并重新获取身份 | 再次创建一个班级 | 继续访问旧 class_id 路由 |

班级彻底删除的目标接口契约是 `DELETE /classes/{class_id}`，请求体、返回值及权限必须以实际 OpenAPI 为准。接口不存在时按前述后端缺口处理，不能在前端猜测或替代实现。

## 四、统一 API 客户端

实现唯一的 `api()` 请求封装：

- 自动拼接 `/api/v1`。
- 自动附加 Bearer Token 和 `X-ClassClaw-Surface: web`。
- 支持 JSON、FormData、文件上传和无请求体调用。
- 解析统一响应格式。
- 保留并在错误详情中显示 `request_id`，便于后端排错。
- 每个页面支持 loading、empty、error、success 四种状态。
- 同一按钮请求期间禁用，防止重复提交。
- 对幂等操作提供稳定 idempotency key，而不是每次重试随机创建新业务记录。
- 不在控制台打印令牌、密码、附件内容或学生敏感信息。

成功响应：

```json
{
  "success": true,
  "data": {},
  "message": "操作成功",
  "request_id": "..."
}
```

错误响应：

```json
{
  "success": false,
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "...",
    "details": {}
  },
  "request_id": "..."
}
```

必须单独处理：

- `OPENCLAW_CONNECTION_REQUIRED`：页面进入只读/阻止态，并提供“重新检查 OpenClaw”。
- `PENDING_CONFIRMATION_REQUIRED`：onboarding 或聊天 proposal 已过期/冲突时进入对应复核状态；普通网页领域写入不要因此自动改走 proposal。
- `CLASS_LIMIT_REACHED`：说明一个班主任只能拥有一个班级。
- 班级删除相关冲突：长期显示后端 message、details 和 request_id；删除失败时旧班级仍保持当前上下文，绝不提前切换到 onboarding。
- `ONBOARDING_ALREADY_EXISTS`：提供恢复未完成 onboarding 的入口。
- `CLASS_NAME_CONFLICT`、`OPENCLAW_AGENT_CONFLICT`：在班级名称输入阶段直接显示。
- `STUDENT_AMBIGUOUS`：显示候选学生，不自动选择。
- `DATABASE_BUSY`：提示稍后重试，不伪装成保存成功。
- `WECHAT_QR_UNAVAILABLE`：提供重新生成二维码操作。

## 五、Web 直接写入、聊天复核与危险操作

不要把 OpenClaw 聊天审批规则错误套到网页结构化表单上。当前产品有三种不同写入方式：

### 1. 普通网页结构化操作

用户已经在网页表单、座位网格或课表矩阵里明确选择字段，因此直接调用对应领域接口；成功后重新 GET 真实数据。不要额外创建 proposal，不要让用户再经历“智能体确认”或 OpenClaw 审批卡。

典型直接写入包括：学生、座位快照与交换、课表、作业与收缴状态、考勤、学生事件、考试成绩、调课、值日、安排完成等。具体以 `/openapi.json` 为准。

```text
填写/编辑结构化页面
→ 页面内完成字段校验和影响摘要
→ 直接调用真实领域 API
→ 后端成功
→ 重新 GET 列表/详情
```

批量操作仍需在提交按钮附近显示数量和范围，例如“保存 38 名学生的语文作业状态”，但这属于网页交互确认，不创建 `write_proposals`。

### 2. onboarding 最终创建班级

班级创建仍使用后端 onboarding proposal，因为它需要把班级、学生、科目、节次、基础课表和 Agent 绑定记录放在同一事务中：

```http
POST /class-onboarding/sessions/{id}/preview
POST /write-proposals/{proposal_id}/confirm
```

只有最终创建班级使用这个网页 proposal。草稿中的名单、节次、课表和初始座位布局可以反复编辑，不应每改一个单元格就生成 proposal。

### 3. OpenClaw/微信聊天写入

聊天里的自然语言写入由 Agent 展示一次简短预览；用户在聊天中明确肯定后，Agent 调用 `classclaw_commit_write` 或 `classclaw_commit_writes`。这套流程不属于普通网页表单，网页也不显示 OpenClaw 审批卡。

### 4. 真正危险的网页操作

班级彻底删除、停用账号、重置密码、覆盖整张课表、恢复历史座位等操作使用页面内二次确认 Modal。确认文案必须写出对象、影响范围和不可逆性。二次确认只是前端防误触，仍直接调用后端对应接口，不得伪造成功。

共同规则：

- 所有写入以真实 HTTP 成功响应为准；失败时保留表单和当前业务上下文。
- 不做乐观插入来假装后端已保存；可以显示局部 saving 状态。
- 不能因为参考 Prompt 描述了某个功能，就调用不存在的接口。
- 接口缺失时明确显示后端缺口，不用 localStorage、假数据或相似接口冒充。

从参考工作台提取“治愈、可信、轻量”的教育产品风格，但不要复刻单文件 localStorage 应用。

默认使用“山野青”主题：

```css
:root {
  --primary: #176A52;
  --primary-dark: #0F503E;
  --primary-soft: #E9F4EE;
  --bg: #F7F7F1;
  --surface: rgba(255,255,255,.92);

  --muted: #667A73;
  --border: #DCE4DF;
```

要求：

- 背景温和，卡片高对比，不能为追求“毛玻璃”牺牲可读性。
- 中文正文使用系统字体；数字指标使用清晰的等宽或系统数字字体。
- 卡片圆角 16–20px，按钮 10–12px，阴影轻柔。

- 支持 `prefers-reduced-motion`，动画控制在 150–250ms。
- 表单、按钮、抽屉、Modal、标签页、表格均可键盘操作，有可见 focus 样式和正确 aria 属性。

- 满屏高饱和渐变。
- 大量无意义装饰图表。
- 把所有操作挤在一张超宽表格。
- 原生 alert、confirm、prompt 作为主要交互。
- 只有 hover 才能发现的核心操作。

## 八、登录、首次使用与路由守卫

### 1. 登录页

- 品牌、系统用途、用户名、密码、登录按钮。
- 默认值不能在生产代码中自动填入密码。
- 提供“默认管理员首次登录：admin / 32767”的部署提示，但密码字段为空。
- 请求期间禁用按钮。
- 登录失败显示后端 message 和 request_id。

### 2. 登录恢复

- 页面启动调用 `/auth/me`。
- 有效则恢复角色和班级上下文。
- 无效则清除 token 并显示登录页。

### 3. 班主任首次使用

- 登录恢复后以 `/auth/me.class_id` 和 `/classes` 交叉核对班级状态。已有班级时直接显示该班工作台；不要先闪现 onboarding，也不要让用户选择班级。
- `class_id` 为空时不显示空洞业务菜单，进入欢迎页。
- 欢迎页说明“账号由管理员创建；一个班主任账号同时只能有一个班级”，提供唯一主操作“创建班级”。
- 如果已有未完成 onboarding，会话列表中提供“继续填写”。
- onboarding 完成后先创建 Agent；微信绑定是可选项。跳过时显示“暂未绑定”，不得显示假绑定成功。

### 4. 班级生命周期

- 班级设置页提供清晰分开的“停用班级”和“彻底删除班级”，仅展示 OpenAPI 中真实存在的能力。
- 彻底删除使用危险操作 Modal：显示班级名称、学生数量、智能体/微信绑定和会被删除的关联数据；要求用户重新输入完整班级名称后才能提交。
- 删除成功后立即清除当前班级状态，重新获取 `/auth/me`、`/classes` 和 onboarding sessions，进入无班级欢迎页，允许创建新班级。
- 删除失败、网络中断或接口缺失时不清除旧班级，不显示“删除成功”。
- 当前后端若尚无真正 DELETE 接口，只显示禁用入口与“后端尚未开放彻底删除”；绝不能调用 `/deactivate` 后对用户宣称已彻底删除。

### 5. 管理员首次使用

- 仪表盘显示用户数、班级数、智能体状态、数据库表数和 OpenClaw 状态。
- 快捷操作：添加班主任、查看未分配历史班级、检查失败智能体、打开数据库调试。

## 九、班级 onboarding 完整流程

新班级只能使用网页 onboarding，不得调用 `POST /classes`。

流程：

1. `POST /class-onboarding/sessions` 创建会话。
2. 填写班级名称、年级、班主任、教室、学期和日期。
3. 班级名称输入后防抖调用 `/class-onboarding/name-check`。
4. 上传学生名单到 `/class-onboarding/sessions/{id}/files`，`target_section=students`。
5. 在结构化学生表中核对、增删、编辑；同名学生必须同时显示学号以便区分。
6. 上传课表到同一文件接口，`target_section=timetable`。
7. 不用扁平明细表作为主要课表编辑器。把 `periods + base_timetable` 转成直观矩阵：横轴固定周一至周五，纵轴按 `sort_order、period_no` 排序；单元格主体显示科目，任课老师以较小文字显示在科目旁边或下方，教室作为可选辅助信息。点击单元格直接编辑科目、老师、教室；空单元格可添加，清空则删除对应 `(weekday, period_no)` 项。
8. 提供“初始座位”步骤：顶部是横向讲台/黑板，下面是面向讲台的多行座位。可设置行列、拖拽学生、点击空座选人、点击两名学生交换、移出座位，并持续显示“未排座学生”。onboarding 阶段用 `student_no` 而不是尚不存在的学生 UUID 保存 `initial_seating` 草稿。
9. `PATCH /class-onboarding/sessions/{id}` 保存草稿，必须携带 `expected_revision`。学生、课表、节次和 `initial_seating` 都使用 `replace_lists=true` 保存当前完整编辑结果。
10. `/preview` 生成最终 proposal。
11. 展示学生数、科目数、节次数、课程数、初始座位已排/未排人数、缺失字段、验证错误和低置信度证据。
12. 用户勾选声明并再次输入班级名称。
13. `/write-proposals/{id}/confirm` 确认创建。
14. 班级创建成功后，获取真实学生列表，把 `initial_seating` 中的 `student_no` 精确映射为学生 UUID，再调用 `POST /classes/{class_id}/seating` 创建第一张座位快照。若这一步失败，班级不能回滚或重复创建；显示可恢复的“完成初始座位设置”入口。
15. 自动调用 `/classes/{class_id}/agent-binding/provision` 创建独立 Agent，并提供“绑定微信”和“暂不绑定微信”。
16. 仅在用户选择绑定时调用 `/start` 并显示真实 `qr_data_url`，随后由网页自动轮询 `/wait`；扫码成功后自动完成消息路由，不显示手动检查按钮。
17. 完成后进入工作台。

必须处理：

- 列表上传是“本次文件完整替换”，不能把旧识别结果合并回来。
- 结构化表格人工修改不再次调用模型。
- 修订冲突时重新加载服务器 revision，不覆盖他人修改。
- 页面刷新后能从会话列表恢复。
- `initial_seating` 是 onboarding 草稿中的扩展 UI 数据；当前班级创建事务不会自动落座位表，必须执行第 14 步。不得把学号直接写入正式 `layout`，正式座位只能保存学生 UUID 或 `null`。
- 二维码加载失败有明确提示和重新生成按钮。
- 智能体名称显示友好身份名，但不要把班级名当作 OpenClaw 资源 ID。

## 十、页面模块规格

### 1. 今日仪表盘

使用真实接口汇总：

- 班级学生数和近 7 天事件：`GET /classes/{id}/summary`
- 今日最终课表：`GET /classes/{id}/timetable/daily?lesson_date=...`
- 今日值日：`GET /duty/today?class_id=...&day=...`
- 安排：`GET /arrangements?class_id=...`
- 早报：`GET /briefings/morning?class_id=...&date=...`
- OpenClaw：`GET /openclaw/status`

首页卡片：学生数、今日课程、待办、逾期、今日值日、待确认；下方展示今日课表、值日、临期安排、关注学生和数据质量。

接口无数据时显示真实空状态，禁止生成演示数字。

### 1.1 班级设置与彻底删除

班主任只有一个当前班级，因此班级页面是“当前班级设置”，不是多班卡片列表。可编辑班级名称、年级、教室、班主任和学期字段时调用当前 OpenAPI 的真实更新接口。

危险区同时解释“停用”和“彻底删除”的区别。产品最终规则是：彻底删除后该账号没有班级，可以重新 onboarding 创建一个班级。只有 OpenAPI 提供真实彻底删除接口时才启用按钮；成功后按“班级生命周期”规则清空上下文。管理员查看所有班级时可以使用表格，但不能改变普通班主任的一账号一班级体验。

### 2. 学生档案

接口：

```text
GET /students
GET /students/{id}
```

支持搜索、状态、标签和姓名精确查询；列表显示学号、姓名、性别、住宿、小组、标签和状态。点击打开详情 Drawer，展示基础资料及后端聚合的座位、值日、作业、考勤、表现、成绩和关注摘要。

网页新增、编辑和删除直接调用学生领域接口；删除前显示学生姓名、学号和“当前为软删除”的影响说明。成功后重新查询列表。

### 3. 座位表

接口：

```text
GET /classes/{id}/seating/current
GET /classes/{id}/seating/history
GET /seating/{snapshot_id}
```

座位表必须先让人“一眼看出这是一间教室”，不能退化成普通数据表：

```text
                 黑板
        ┌──────────────────┐
        │       讲 台       │
        └──────────────────┘

  第1排   [01 张三] [02 李四]   [03 王五] [04 空座]
  第2排   [05 …… ] [06 …… ]   [07 …… ] [08 ……]
                       ↓ 教室后方
```

- 讲台固定在顶部并面向下面所有座位；第 1 排最靠近讲台。显示行号、座位序号、学生姓名和学号，空座使用明显但克制的虚线卡片。
- 桌面端在可用宽度内尽量完整展示教室；座位很多时容器内部缩放或横向滚动，不能把讲台与座位拆散。移动端允许横向滚动，并提供“适应宽度/100%”切换。
- 编辑态支持：调整 rows/cols、拖拽换座、点击空座选择学生、点击已占座移出/换人、学生搜索、未排座学生池、撤销本次未保存修改、填写 `change_note`。
- 每名学生最多出现一次；删除行列前显示将被移出的学生；保存前校验矩阵必须严格为 `rows × cols`，每格只能是当前班学生 UUID 或 `null`。
- 保存整张布局直接调用 `POST /classes/{id}/seating`；两人快速交换可调用 `/seating/swap`；不要为网页编辑创建 proposal。保存成功后重新获取 current snapshot。
- 历史以时间轴展示，点击只读查看；恢复历史调用真实 restore 接口并使用页面内二次确认。
- 可以用 CSS 将相邻两个座位视觉分组为课桌、用较大 gap 表示过道，但这些只属于显示层。后端没有 `desk`、`aisleCount` 字段，不得保存或伪造这些字段。

### 4. 值日管理

页面页签：规则、排班预览、今日/本周、评分与统计。

```text
POST /duty/rules/validate
GET  /duty/assignments
GET  /duty/today
GET  /duty/weekly
GET  /duty/statistics
```

展示结构化规则 JSON 的友好表单和高级 JSON 折叠区。网页排班确认直接调用真实 confirm 接口；评分、临时替换、完成登记等按当前 OpenAPI 直接调用并刷新，不创建聊天 proposal。

### 5. 作业管理

接口：

```text
GET /homework
GET /homework/{id}/summary
GET /homework/{id}/missing
```

网页创建作业直接调用 `POST /homework`，学生状态批量更新直接调用 `PUT /homework/{id}/students`。页面显示截止时间、状态、完成率、未交/迟交/订正人数和学生清单。

### 6. 学生日常表现

```text
GET /student-events
```

提供日期范围、学生、类型、科目、情绪和严重程度视图。网页单条/批量登记直接调用学生事件领域接口。正向、普通关注、严重事件使用明确但不过度标签化的视觉。

### 7. 考勤

```text
GET /attendance
GET /attendance/summary
```

支持日期、时段和状态筛选。网页录入直接调用 `PUT /attendance`。时段固定：`full_day`、`morning`、`afternoon`、`recess`、`care_1`、`care_2`；状态固定：`present`、`late`、`absent`、`leave`。

大课间不计全天出勤率，不在前端自行用错误分母重算；优先展示后端统计。

### 8. 成绩与考试

```text
POST /exams
GET /exams/{id}/scores
GET /exams/{id}/statistics
```

网页创建考试直接调用 `POST /exams`；批量成绩直接调用 `POST /exams/{id}/scores`。录入表格必须校验学生、科目、分数和满分，显示整批记录数，任何失败都保留用户输入供修正。

当前后端没有 `GET /exams` 考试列表接口。页面不得伪造考试列表；只能展示当前会话中创建成功后已知的考试 ID，或明确展示“后端尚缺少考试列表接口”的阻止态，并把该缺口写入最终交付报告。

统计显示平均分、最高/最低、及格率和排名；不实现后端没有数据的知识点失分、选科或增值榜。

### 9. 课表与调课

```text
GET /classes/{id}/periods
GET /classes/{id}/timetable/base
GET /classes/{id}/timetable/daily
POST /lesson-swaps/preview
POST /lesson-batch-changes/preview
```

基础课表、节次和临时调课在网页端使用真实领域接口直接保存。互换和长期调课先调用后端 preview，把影响日期、原课程、新课程和冲突长期展示在页面内；用户确认后再调用对应 confirm。这里的 preview 是领域预览，不是 `write_proposals`，也不需要 Agent 审批。

课表主视图必须是固定语义矩阵，不得以扁平 API 行列表代替：

```text
┌────────────┬────────┬────────┬────────┬────────┬────────┐
│ 节次/时间   │ 周一    │ 周二    │ 周三    │ 周四    │ 周五    │
├────────────┼────────┼────────┼────────┼────────┼────────┤
│ 第1节       │ 语文    │ 数学    │ 英语    │ ……      │ ……      │
│ 08:00-08:45│ 李老师  │ 王老师  │ 陈老师  │         │         │
├────────────┼────────┼────────┼────────┼────────┼────────┤
│ 第2节       │ ……      │ ……      │ ……      │ ……      │ ……      │
└────────────┴────────┴────────┴────────┴────────┴────────┘
```

- 横轴默认只显示周一至周五；若真实数据包含周六/周日，放入“周末”折叠区，不挤乱主矩阵。
- 纵轴严格按 `ClassPeriod.sort_order`、`period_no` 排序；第一列显示节次名称，后端没有开始/结束时间字段时不要虚构时间。
- 每格科目是主信息；`teacher` 用较小但清晰的文字紧贴科目显示，`room` 可作为第三行。任课老师为空就不占位，不写“未知老师”。
- 不同科目可使用稳定柔和色，但必须保留文字，不能只靠颜色区分。
- 编辑态点击单元格打开小型 Popover/Drawer，可修改 subject、teacher、room；支持键盘在相邻单元格移动、复制上一格和清空。保存时把矩阵规范化为唯一 `(weekday, period_no)` 的 `items[]`，调用 `PUT /classes/{id}/timetable/base` 整体替换。
- 节次在矩阵左侧就地增删改和排序。因为当前 `PeriodCreate` 只有创建接口而未必有更新/删除接口，必须以 OpenAPI 为准；缺少接口时允许新增，已有节次只读，不能仅在本地假装已改。
- onboarding 与正式课表复用同一个 `TimetableGridEditor`，区别只在数据适配器：onboarding 写入 `draft.periods/base_timetable`，正式页调用课表 API。不要维护两套视觉和编辑逻辑。
- 每日课表复用同一矩阵/课程卡视觉，明确标记临时变更、取消与原因；不要暴露 UUID 或 `lesson_key` 作为主文案。

### 10. 日常安排

```text
GET /arrangements
```

按待处理、进行中、完成、逾期分组；支持日期和优先级。网页新增直接调用 `POST /arrangements`。展示最多三个提醒时间；未指定时展示默认提前三小时一次。用户可在网页编辑结构化提醒时间，但用户可见的临近提醒统一由班级 Agent 主动发送，后端只保存计划和状态；当天事项还应出现在早报 `today_reminders`。

### 11. 附件

```text
POST /attachments
POST /attachments/{id}/links
```

支持拖拽、文件大小提示、上传进度、SHA-256/类型/大小结果和关联实体表单。不要在浏览器读取或展示服务器文件系统绝对路径；普通班主任不进入管理员数据库调试接口查看附件路径。

### 12. 分析和早报

```text
GET /analytics/students/{id}/comprehensive
GET /analytics/students/{id}/compare
GET /analytics/classes/{id}/comprehensive
GET /analytics/classes/{id}/compare
GET /analytics/classes/{id}/attention-students
GET /analytics/classes/{id}/cross-module
GET /analytics/classes/{id}/data-quality
GET /briefings/morning
```

筛选支持预设 7/14/30 天、本周、本月、自定义时间和比较周期。分析结果必须展示：时间范围、覆盖度、指标、趋势、证据、警告。相关性不得写成因果关系；数据不足要原样展示 warning。

图表使用原生 SVG/CSS，必须同时提供数值表格或文本，不能只靠颜色。

### 12.1 快捷查询中心

这是班主任高频使用入口，不是管理员 JSON 调试页，也不是没有后端支持的假自然语言搜索。使用“查询模板 chips + 结构化条件 + 结果表/学生卡”组合，允许用户一两次点击得到答案。

必须实现以下真实用例：

1. **今天未交作业的学生**
   - 先用 `GET /homework?class_id=...` 获取相关作业，在前端明确区分“今天布置”和“今天截止”；默认查询今天截止或今天仍需处理的已发布作业。
   - 对命中的每条作业调用 `GET /homework/{id}/missing`，再与学生列表按 `student_id` 精确关联。
   - 结果按科目/作业分组，显示学生姓名、学号、作业标题、布置日期和截止时间；提供科目筛选。

2. **某个科目未交作业的学生**
   - 调用 `GET /homework?class_id=...&subject=语文`，再查询对应 missing 列表。
   - 支持日期范围、作业状态和“仅当前仍未交”；不要把 `pending` 自动当作 `missing`。

3. **前天上课睡觉的学生**
   - 用 Asia/Shanghai 本地日期计算前天，调用 `GET /student-events?class_id=...&start_date=前天&end_date=前天&event_type=behavior`。
   - 当前接口没有 subtype/content 服务器筛选时，只在这个已限定单日结果集内按 `subtype` 或 `content` 的“睡觉”关键词做客户端筛选，并在代码注释中说明。
   - 显示学生、学号、科目、实际事件日期、内容和严重程度；禁止改用消息接收时间。

4. **某位同学最近具体表现**
   - 姓名/学号搜索先调用 `GET /students`；同名时显示候选人，不猜。
   - 详情使用 `GET /students/{id}` 的近期事件、考勤、作业、成绩、值日和关注项，并可补充 `GET /analytics/students/{id}/comprehensive?start_date=...&end_date=...`。
   - 默认最近 14 天，可切换 7/30 天；按时间倒序列出“发生了什么”，再显示简短汇总，不只给抽象分数。

查询中心还应提供可组合筛选：日期/日期范围、学生、学号、科目、事件类型、关键词、考勤状态、作业状态。每次显示当前查询口径和命中数量，支持一键清空。结果为空要说“当前条件下没有记录”，不要说“该生从未发生过”。

性能规则：先用后端现有筛选参数缩小范围，再做小规模客户端关联；同一批 homework missing 请求可限制并发并缓存到当前页面生命周期。切换班级、退出登录或数据写入成功后清除相关查询缓存。不得下载全数据库后在浏览器中搜索。

若设计一个自然语言样式的输入框，它只能把用户选择映射到上述已知模板；未支持的问题应引导用户使用结构化筛选或微信 Agent，不能伪装成通用语义查询。

### 13. 工作流和审计

```text
GET /write-proposals/{id}
GET /audit-logs                 # 仅管理员
```

工作流页仅用于查看 onboarding 最终 proposal 和由微信 Agent 生成的聊天 proposal，不把普通网页保存包装成待确认流程。写入预览显示问题、缺失字段、过期时间和载荷摘要；不展示或要求后端保存消息原文。审计仅显示操作人、动作、实体和时间，不假定存在完整的前后 JSON 快照，也不提供通用撤销入口。

### 14. OpenClaw 与微信

```text
GET  /openclaw/status
GET  /classes/{id}/agent-binding
POST /classes/{id}/agent-binding/provision
POST /classes/{id}/agent-binding/start
POST /classes/{id}/agent-binding/wait
```

显示 Gateway、插件、Agent、微信账号、绑定状态、最近二维码时间和错误。二维码必须使用后端返回的 `qr_data_url`；网页自动轮询绑定状态，轮询请求不重复提交大 PNG。

状态文案区分：`pending_agent`、`agent_created`、`awaiting_qr`、`linked`、`failed`。

## 十一、管理员页面

### 1. 用户管理

```text
GET   /admin/users
POST  /admin/users
PATCH /admin/users/{id}
POST  /admin/users/{id}/reset-password
POST  /admin/users/{id}/assign-class
```

功能：

- 管理员是创建账号的唯一入口。系统不提供公开注册，班主任也不能邀请或创建其他账号。
- 创建班主任；用户名在提交前做格式提示，后端以规范化后的唯一约束为准。`USERNAME_CONFLICT` 必须显示在用户名字段下，不能只弹 Toast。
- 默认密码提示为 `32767`，创建成功后提供一次性的交付提示，但不在列表永久显示密码。
- 启用/停用。
- 重置密码前二次确认，说明旧会话将失效。
- 为迁移前历史班级分配班主任。
- 列表显示账号、角色、显示名、班级、状态、首次改密状态、最近登录。
- 班级列只有“未创建”或一个真实班级；不提供多班选择。未创建班级的账号登录后应看到创建入口，已有班级账号登录后直接看到班级。
- 班级彻底删除后刷新该用户行，班级列变为“未创建”；此后该用户可重新 onboarding。管理员不能直接给一个已有班级的账号再分配第二个班级。

唯一管理员不可通过普通用户管理按钮停用或重置。

### 2. 智能体管理

```text
GET  /admin/agents
POST /admin/agents/{class_id}/wechat/start
```

按正常、待扫码、失败分组。卡片显示班级、所有者、Agent ID、展示名、workspace（只在管理员详情中显示）、微信账号、错误和更新时间。失败时提供刷新配置/重新生成二维码。

不要提供后端没有实现的“删除 Agent”网页按钮。

### 3. 数据库调试

```text
GET /admin/database/overview
GET /admin/database/tables/{table_name}?offset=0&limit=50
```

功能：表清单、行数、分页、列名、行 JSON 展开、复制 ID。必须明确“只读”；不提供 SQL 输入、不提供单元格编辑、不提供删除按钮。

`password_hash` 和 `token_hash` 必须保持后端脱敏结果，前端不能尝试请求或推断原值。

## 十三、组件规范

至少实现以下可复用组件：

- `PageHeader`：标题、说明、主操作。

- `SeatMapEditor`：讲台/黑板、座位网格、未排座学生池、拖拽/点击编辑、矩阵校验和只读历史模式；onboarding 与正式页面复用。
- `TimetableGridEditor`：周一至周五横轴、节次纵轴、科目/任课老师/教室单元格；onboarding 与正式页面复用。
- `Modal`：表单和二次确认。
- `Drawer`：学生和业务详情。
- `ProposalReview`：仅用于 onboarding 最终创建和聊天 proposal 的预览；普通 Web 保存不得调用。
- `StatusBadge`：状态映射集中管理。
- `ErrorPanel`：错误码、message、details、request_id 和重试。
- `FileDropzone`：拖拽、选择、上传进度和结果。
- `QrBindingPanel`：二维码、错误、刷新和状态轮询。

- `EmptyState`：说明原因和下一步。

- `Toast`：短暂非关键反馈。

- 有标题和关闭按钮。
- Escape 可关闭非提交中 Modal。
- 焦点进入后留在 Modal 内，关闭后返回触发按钮。
- 遮罩点击关闭时不能丢失已提交中的请求。
- 移动端高度超出时内部滚动。

## 十四、状态、筛选和空数据

- 当前班级、当前用户和 OpenClaw 状态存于内存状态，刷新后重新从 API 获取。
- 页面路由可使用 hash，例如 `#/students`，刷新后仍回到同模块。
- 筛选条件可写入 URL 查询参数，便于返回和分享；不得包含令牌或敏感学生信息。
- 每个列表提供清空筛选。
- 日期范围默认值必须在 UI 中可见。
- 新空数据库是正常状态；管理员看到“添加第一个班主任”，班主任看到“创建第一个班级”。
- 不自动生成演示班级、学生、成绩或考勤。
- 后端返回空数组时不能当成异常。

---

## 十五、安全与隐私

- 不把 access token 放进 URL、日志或 DOM 文本。
- 密码字段禁止回显；修改密码后清空输入。
- 学生电话和家庭信息只在详情页展示，列表按需省略或遮蔽。
- 数据库调试仅管理员可见。
- 下载/展示附件前验证 URL，后端未提供下载 URL 时不自行拼接服务器路径。
- 不能让用户输入任意 SQL、Python、文件系统路径或 OpenClaw 管理 RPC 方法。
- 所有批量和危险操作明确展示影响范围。
- 不用前端角色判断替代后端权限。
