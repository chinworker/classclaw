# 班级监控、点名广播与 Windows 教室终端计划

状态：原始设计与现场验收计划。**服务端、网页、Agent/Channels、MediaMTX 分轨接入和按需单帧 AI 概况均已实现**，当前协议以 [服务端实现](classroom-monitoring.md) 和 [媒体部署](classroom-media-deployment.md) 为准。Windows 终端现已实现于 [classroom-mate](../classroom-mate/README.md)，真实硬件仍待验收；历史候选方案中的 RTSPS 上行已确定为经 ClassClaw 认证的 WHIP/WebRTC，短音频概况不在当前交付范围。当前客户端采用低分辨率软件编码，历史规划中的硬件编码、免转码、姓名读音配置尚未实现。

## 1. 已确认的需求

- ClassClaw 部署在服务器，教室里有一台配置较低的 Windows 电脑。
- 教室电脑不是学生日常使用的电脑。Windows 软件正常登录后自启，不弹出主窗口，自动驻留托盘；不需要权限分离、禁止退出或防卸载。
- 点名是“点名广播/叫人办事”：老师告诉 Agent，或在网页单选、多选学生，以“称谓＋时间＋谓词（事项）”组成完整句子，或直接填写自定义句子；教室屏幕显示全文，扬声器播报相同内容。不属于考勤，也不只播报姓名。
- 摄像头的选择、连接、更换和断开统一在网页操作；每个班级最多连接一个摄像头，Windows 负责检测并执行，Agent 使用本班已连接的摄像头，不自行切换。
- 复用现有摄像头和声音来源，目前教室电脑使用掌上看家且能够工作；型号和接入方式不明。优先通过 Windows 接口检测并读取可用摄像头/麦克风，不要求老师先提供设备型号。需要在网页查看视频并按需听到现场声音。
- 可以控制教室 Windows 音量，方便点名播报。
- 网页 Chat、微信及后续 ClassClaw Channels 都能访问点名、设备状态及教室概况能力。

首期按一班一个教室终端、一路摄像头画面和一路现场声音设计。摄像头最初被描述为网络摄像头，但物理接入方式尚未确认；不能仅凭“可远程观看”认定是独立 IP 摄像头。Windows 设备检测、音频能力、系统版本和网络条件由现场验证确定。

## 2. 推荐架构

建议做轻量 Windows 软件 **ClassClaw Classroom**，承担摄像头/麦克风检测、按需采集或转发、广播句子显示、播报和音量控制；业务和 AI 分析放在服务器。

```text
网页点名 / 网页 Chat / 微信 / 其他 ClassClaw Channels
                    │
                    ▼
        ClassClaw 服务器 / 本班 Agent
             │                │
             │ WSS 指令       │ 鉴权、媒体观看会话
             ▼                ▼
      Windows 托盘程序      媒体转发组件 ──→ 网页实时监控
        │         │              ▲
        ▼         ▼              │
      显示屏     扬声器       现有摄像头画面和现场声音
                             （优先 Windows 采集；支持网络流适配）
```

Windows 终端是执行设备，不为它另建一个班级 Agent，也不在低配置电脑上运行 OpenClaw 或本地大模型。所有渠道访问同一班级的设备、名单和记忆，设备绑定与微信等渠道账号绑定分别建模。

继续使用现有单进程 FastAPI、SQLite 和 Service 分层，不引入 Redis、Celery、消息队列、向量数据库或业务微服务。实时媒体建议增加同机 MediaMTX 转发进程，采用普通可执行文件部署；这是现有部署依赖的明确扩展，实施时要同步运维文档。FastAPI 负责权限和控制，不逐帧转发视频。

## 3. Windows 端

### 3.1 程序形态

建议 C#/.NET + WinForms 托盘界面，显示层也使用原生窗口；具体运行时按现场 Windows 版本选择受支持版本，不预先承诺兼容旧系统。避免 Electron 和常驻浏览器。

- 安装时提供“登录 Windows 后自动启动”，默认启用。
- 启动后只有托盘图标，不抢焦点、不弹主窗口；双击图标打开设备状态与设置。
- 关闭设置窗口回到托盘；托盘菜单提供设置、连接测试、显示测试、播报测试、暂停与正常退出。
- 网络断开后自动退避重连，程序保持正常托盘运行；不采用互相拉起、进程隐藏或阻止任务管理器的机制。
- 首期不用 Windows 服务。普通托盘程序在用户登录后启动，不能在无人登录时显示姓名或向桌面用户播报。开机后未进入 Windows 桌面时，服务器应显示终端未就绪，不做自动登录管理员账号。
- 如果网络摄像头由教室电脑中转，电脑关机、程序退出或用户注销后该中转会中断；若要求电脑关闭时监控仍可用，需要独立的摄像头网络接入路径。

Windows 服务不能直接承担现代桌面的交互显示，采用普通会话程序也符合此次“自启到托盘”的实际需求。[微软：Interactive Services](https://learn.microsoft.com/en-us/windows/win32/services/interactive-services)

### 3.2 初次配置

老师在本班设备页面生成短期一次性配对码，在 Windows 设置中输入服务器地址和配对码。服务端发放本设备专用凭据，可撤销和重新配对；终端不持有 ClassClaw 全局共享 Token 或 OpenClaw 管理员 Token。

Windows 端保存少量配置：设备身份、服务器地址、网页下发的摄像头/麦克风设备标识、目标显示屏、扬声器、中文语音、音量上限、可选网络流配置。摄像头连接的权威配置在服务端，托盘界面不另设绕过网页的摄像头绑定入口。凭据在本地加密保存；日志不写凭据、摄像头密码或完整广播文本。

Windows 主动通过 WSS 连接服务器，学校不需要为教室电脑开放公网入站端口。心跳报告版本、连接状态、显示/播报能力、当前输出设备及音量。更新先采用可验证的安装包，不开放远程 shell 或任意执行程序的功能。

### 3.3 显示屏与播报

- 老师预先选择显示屏：教室一体机本屏或外接显示器/投影，不能默认把教师个人副屏当作全班显示屏。
- 广播到达时弹出展示窗口，大字显示完整句子，突出称谓和事项；多选时支持合并成一句或按学生分别生成完整句子。显示内容和播报内容一致，按同一冻结顺序执行。
- 支持停留时长、字体大小、播报次数、句间间隔，以及停止/清除显示。全屏与浮层作为显示模式设置；长句自动换行或分页，不能截掉时间和事项。
- 展示结束后关闭点名窗口，回到托盘，尽量恢复原课堂窗口；不强行解锁 Windows 或跨锁屏显示。
- 锁屏、注销、输出设备丢失时分别报告不可显示/不可播报，不将接收成功当作已完成。
- 名字多音字允许老师设置读音修正；先检查 Windows 是否具备可用中文 TTS，没有时明确提示安装语音或选用经批准的服务器生成音频方案。

## 4. 摄像头与声音接入

### 4.1 优先检测 Windows 设备

Windows 枚举设备后上报本班网页，老师在网页“设备检测”界面查看摄像头、麦克风和扬声器，确认设备名称及分辨率/帧率，进行画面预览和短时试听。选择并连接后以稳定标识保存；设备缺失时明确报错，不悄悄切换到其他摄像头或麦克风。

每班最多一个摄像头连接，由数据库班级唯一约束和 Service 校验共同保证；网页限制不能代替服务端约束。更换时显示替换对象，先撤销旧媒体会话并停止旧连接，再启用新连接；切换失败明确报告，不能并行启用第二路或声称更换成功。并发更换按配置版本校验，拒绝过时请求。断开后仍可使用点名广播和音量功能。

优先使用 Windows Media Foundation 获取系统提供的采集设备，必要时使用 DirectShow 兼容路径；FFmpeg 的 DirectShow 输入也支持列出视频和音频设备。正式选择以现场兼容性和低配负载测试为准，不同时长期运行两套采集链路。[微软：枚举视频采集设备](https://learn.microsoft.com/en-us/windows/win32/medfound/enumerating-video-capture-devices)、[FFmpeg：设备输入文档](https://ffmpeg.org/ffmpeg-devices.html)

掌上看家官方同时提供 Windows 采集端与观看端，并介绍了采集端的自启与启动隐藏能力。这支持参考其使用体验，但不能据此推定本机摄像头一定能被系统直接枚举，或推定第三方软件提供通用视频接口。[掌上看家：功能介绍](https://www.ichano.cn/introduce.html)、[官方 Windows 观看端说明](https://wap.ichano.cn/wap/discovery/windowshelp.html)

- 如果目前运行的是采集端，优先验证同一套 Windows 摄像头与麦克风接口能否供 ClassClaw 使用。
- 如果只是观看远端设备，则再确认流地址、RTSP/ONVIF 或厂商正式接口；Windows 不会把任意观看窗口自动变成标准摄像头。
- 检测摄像头隐私权限及设备占用；必要时由老师暂停掌上看家采集后测试，不能强制结束现有软件或承诺两个程序可以同时占用同一设备。
- 计划不读取掌上看家的账号密码、不截取其私有会话，也不默认以录制整个电脑桌面代替教室摄像头画面。

对于确认为独立网络摄像头的设备，进一步验证品牌型号、RTSP/ONVIF、音轨和编码，以及与教室电脑的网络可达性：

- RTSP 用于取得实时流；ONVIF 如可用，可辅助发现设备和读取配置，不能因为有 ONVIF 就假定音视频一定兼容。
- 如果是只支持厂商 App/云端的封闭摄像头，必须查其正式接口；不承诺直接接入。
- 摄像头本身没有麦克风或音轨时，软件不能凭空获取现场声音。可选补充麦克风，但需另做采集与音画同步验证。
- 现场声音可来自选定的 Windows 麦克风或网络摄像头音轨，不能假定两者同时存在。它与 Windows 扬声器播报声音是不同来源，不默认采集电脑系统声音。

### 4.2 接入路径

| 条件 | 路径 | 对教室电脑的影响 |
| --- | --- | --- |
| Windows 可枚举并读取现有摄像头/麦克风（优先验证） | 托盘程序通过系统接口按需采集、编码并向服务器推流 | 本地承担采集与编码；优先硬件编码，并控制分辨率/帧率 |
| 服务器通过校内网络或受控专网可达摄像头 | 服务器媒体组件直接读取摄像头 | 电脑只负责显示、播报和音量，负担最小 |
| 服务器在公网，摄像头只在教室局域网 | Windows 按需读取局域网摄像头，并主动向服务器加密推流 | 优先只转发，避免本地重新编码；程序退出时中转停止 |

先验证 Windows 直接采集，暂不以摄像头型号作为继续设计的前提。若确认是独立 IP 摄像头且服务器可达，再选择服务器直读；公网服务器且摄像头只在局域网时验证 Windows 出站中转，不将摄像头管理端口直接暴露到公网。

建议验证 FFmpeg 读取网络摄像头、MediaMTX 转发、浏览器 WebRTC 播放。Windows 上行候选为经过认证的 RTSPS/TCP；如学校出网限制不允许，评估 WHIP/WebRTC 或受控网络连通方案，并实测 TLS、媒体端口与浏览器兼容。[MediaMTX：FFmpeg 发布](https://mediamtx.org/docs/publish/ffmpeg)

### 4.3 性能和兼容

- 初始目标 720p、10–15 fps、约 0.6–1.2 Mbps；性能或网络不足时降为 480p。网络摄像头优先低码率子码流，Windows 本地采集优先低分辨率模式和硬件编码。
- 视频已是浏览器兼容的 H.264 时尽量直接转发；不让低配 Windows 反复解码、编码。
- 摄像头若为 H.265、带 B 帧的 H.264 或 AAC/G.711 音频，需要验证浏览器支持。必要时先尝试摄像头配置/子码流，其次评估服务器侧转换，不能预先承诺无需转码。
- 浏览器兼容目标为无 B 帧的 H.264 与 Opus。尽量只转换不兼容的轨道，避免全链路重编码。
- 无人观看且没有概况采样任务时，停止上传和转发；网络摄像头自身的工作模式由其原有配置决定。
- 多个观看者共用一路摄像头/教室上行，由服务器分发。按 1 Mbps 估算约 0.45 GB/小时，未计协议开销，服务器出口随观看人数增加。
- WebRTC 还需验证公网地址、UDP/TCP 和必要的 TURN 中继；HTTPS 页面可访问不等于音视频一定可达。

上述编解码和连接限制来自媒体服务文档；参数为待实测目标，不是硬件性能承诺。[MediaMTX：WebRTC 兼容与连通性](https://mediamtx.org/docs/features/webrtc-specific-features)

### 4.4 网页功能与访问范围

新增“教室设备 / 实时监控”页面，展示画面、采样/连接时间、当前声音状态、摄像头与终端分别的在线状态，以及重连提示。

- 视频和现场声音可分别控制。老师明确开启声音后才采集选定麦克风或转发网络摄像头音轨；播放器静音与停止音频采集/转发要区分。
- 观看会话有有效期，绑定登录用户、班级、摄像头和音视频权限；路径本身不能绕过鉴权。
- 视频-only 会话不能收到音轨后仅依靠浏览器静音限制；媒体层须实际执行音轨授权。
- 离页释放本人的观看会话，最后一名观看者离开后短暂宽限再停流；一人关闭不能中断其他人的合法观看。
- 登出、撤权和设备解绑需终止已建立的对应会话；多媒体播放链接不做永久公开分享。
- 默认只提供实时查看，不做全天录音录像。录像回放、保留期限和存储费用另行设计。
- 由学校确定课堂采集范围并告知用途；网页和终端显示当前转发/采样状态，托盘运行不等于秘密采集。

## 5. 点名广播：叫名字并通知事项

### 5.1 三段式句子

“三个词”落实为三个可编辑片段，每个片段可包含多个词，不限制为三个单词：

| 片段 | 网页输入 | 示例 |
| --- | --- | --- |
| 称谓 | 从本班名单单选/多选，结合可编辑称呼形成称谓 | 张三同学；张三、李四同学 |
| 时间 | 常用选项或自行输入 | 现在；下课后；今天大课间 |
| 谓词（事项） | 常用短语或自行输入要做的事情 | 去扫地；来老师办公室；到讲台领取作业 |

默认模板：**请{称谓}{时间}{谓词}。**

- 单选：请张三同学现在去扫地。
- 单选：请李四同学现在来老师办公室。
- 多选合并：请张三、李四同学下课后来老师办公室。
- 多选逐人：分别生成“请张三同学现在去扫地。”“请李四同学现在去扫地。”，逐句显示并播报。

多选默认合并一句，老师可切换逐人播报；网页实时预览最终句子。所选学生、称呼、时间、事项和生成文本一起冻结，发送后不能由客户端重新补全或改写。

这里的“时间”首先是通知内容，**不等于广播执行时间**：“请张三同学下课后来办公室”默认现在显示并播报。只有另行明确要求“下课后再播报”才是定时任务，首期不默默创建定时广播；这类请求应说明当前只支持立即播报。引用“大课间”等约定时可使用本班已确认记忆帮助理解，不擅自改变原文时间。

### 5.2 自定义句子

提供“自定义句子”模式，直接填写完整内容，例如“请今天负责卫生的同学现在带好工具到教室后门集合。”；支持不选择具体学生的班级通知。不强制拆分三个字段，不自动追加“请”“同学”或其他文字。

发送前展示原样预览，屏幕和语音使用同一段文本。设定合理字数和播报时长上限，空内容不可发送；文字仅作为展示和语音内容，不作为脚本、HTML 或设备命令执行。中文姓名读音修正仅影响发音，不改屏幕文字。

### 5.3 网页操作流程

1. 选择“三段式”或“自定义句子”；三段式从本班有效名单中搜索、单选或多选，名单按学号自然排序。
2. 填写称谓、时间、谓词，或直接输入完整句子；实时预览内容并选择合并/逐人、目标屏幕、停留时长和音量。
3. 点击“显示并播报”，由后端校验学生、班级和设备归属，并冻结最终文本与展示顺序后下发。
4. 教室屏幕显示完整句子，扬声器播报相同内容；网页展示真实的显示和播报状态。
5. 支持停止播报及清除屏幕内容；展示结束后恢复课堂界面。

确定性网页操作直接调用领域接口。本模块不创建考勤记录、不判断到场情况，也不因“去扫地”的通知自动生成值日安排或记录任务已完成。

### 5.4 通过 Agent / Channels 广播

用户可说“请 3 号同学现在去扫地，显示并播报”，或“通知张三和李四下课后来老师办公室”。Agent 从本班名单解析对象，提取称谓、时间和事项，展示完整广播句子及目标终端；用户确认后发送冻结文本。指定自定义原文时保留原文；重名、对象或事项不明确时先澄清，不猜测。

业务继续遵循 WriteProposal，但这是广播操作，不映射到考勤接口。广播中的“下课后”与指令中的“下课后再播报”必须区分；确认后不得改人、改时间、改事项或再次让模型润色。只有终端回执才可报告显示/播报完成。

## 6. Windows 音量

- 网页显示选定输出设备、Windows 系统音量和静音状态；支持滑块、静音/取消静音、试播及停止。
- 支持 Agent 指令，例如“把教室电脑音量调到 40%”，预览确认后执行并返回设备实际值。
- 使用 Core Audio 调整指定输出设备的系统主音量；播报应用自身音量单独处理，避免仅调整播放器却称为改了 Windows 音量。
- 支持播报临时音量和结束恢复，并设上限。恢复前检查当前输出设备和音量，不能覆盖老师在播报过程中手动调整的值。
- HDMI、蓝牙或 USB 输出设备变化时重新确认目标，避免画面在教室屏幕、声音却播到其他设备。
- 播报结束、失败或程序恢复后处理临时音量状态；物理音箱关闭等情况不能仅依据 Windows 音量值宣称全班已经听到。

Windows 提供端点主音量及应用音频会话控制接口，具体支持须在现场声卡上验证。[微软：Endpoint Volume Controls](https://learn.microsoft.com/en-us/windows/win32/coreaudio/endpoint-volume-controls)

首期不做实时双向语音对讲。摄像头可能拾取点名播报声，概况分析需区分设备正在播报的状态，避免当成课堂异常。

## 7. ClassClaw Channels 与教室概况

| 请求示例 | 能力 | 反馈 |
| --- | --- | --- |
| “教室电脑在线吗？” | 读取终端心跳 | 最后在线时间、显示和播报是否就绪 |
| “摄像头现在正常吗？” | 读取摄像头/流状态 | 连通状态、视频/音频能力及更新时间 |
| “看看教室监控” | 提供本班网页查看入口 | 必须登录并校验权限；微信不支持原生播放时提供网页入口 |
| “请 3 号和 8 号同学现在去扫地，显示并播报” | 学生解析与句子生成 → 完整文本预览 → 确认 → 终端执行 | 依据终端回执报告显示及播报结果 |
| “教室音量调到 40%” | 变更预览 → 确认 → 终端执行 | 设备回报的实际音量 |
| “现在教室大致什么情况？” | 本次授权的短时截图采样 → 服务器模型分析 | 时间、可见的整体情况、遮挡/模糊及不确定性 |

状态查询和查看按媒体权限执行；点名、音量等写操作遵循现有预览确认。请求声音概况时才短时接入音频，不能因查看画面而自动采集声音。

概况第一版提供设备状态和真实画面，后续再接按需 AI 描述。取少量当前截图、明确请求的短音频，不持续将整节课上传给模型，不在教室电脑部署大模型。云端分析的处理方式由学校配置明确，采样用专用短期缓存并自动清理，不复用长期保留的聊天附件。

只描述现场可观察的整体情况，例如画面遮挡、有人走动、明显环境声音；不对学生生成个人情绪、专注度或纪律评分，不以画面分析代替考勤。旧截图不能称为当前实况，画面不清楚就明确说明。AI 分析失败不影响网页实时监控、点名和音量。

## 8. 服务端与数据设计

建议增加以下模块，具体命名在实现时确定：

| 模块 | 内容 |
| --- | --- |
| 设备管理 | 终端配对、凭据撤销、心跳、显示/音频能力 |
| 摄像头管理 | 网页连接/更换/断开、每班唯一摄像头约束、版本校验、音轨能力、接入路径 |
| 终端执行 | 显示/播报、停止、清除、设置音量等固定动作 |
| 媒体会话 | 用户与班级鉴权、音轨权限、短期观看租约、停止转发 |
| 广播记录 | 模式、所选学生、称谓/时间/谓词或自定义句子、最终冻结文本、显示/播报顺序、操作者及执行结果；不写考勤 |
| 概况采样 | 授权范围、短期样本、结构化摘要与到期清理 |

新增实体必须有 Alembic 迁移。业务数据继续写 SQLite；媒体只流式转发或放短期文件，不将视频写进数据库。摄像头密码应加密保存或使用专用密钥配置，不回传浏览器/模型、不记日志。

摄像头地址由受权配置流程登记，读取服务只访问已登记的目标和协议，防止任意 URL 读取、SSRF 或将摄像头密码用于其他主机。当前只有 admin/head_teacher 两类角色，不额外创造学校组织权限系统。

终端只持有本设备凭据，只能接收自己的命令、上传自己的状态；命令校验设备、班级、固定类型、参数范围、有效期及幂等 ID。禁止将模型生成的 shell、路径或任意可执行命令下发终端。

控制连接在线直接投递，SQLite 保存执行账本，不建立消息队列或离线命令积压。离线时拒绝实时点名/音量操作，恢复网络后不补播上一节课的点名。

数据库提交与物理显示/播报不能形成同一原子事务：明确区分“授权并登记、送达、执行中、成功、失败、过期、结果未知”。提案完成不等于已发出声音。终端以命令 ID 去重，回执丢失时先查询状态，未知时不自动重播；显示和声音结果分别返回。

服务端不持有 SQLite 写锁等待终端、媒体或模型。终端退出、网络断开、服务器重启后处理过期命令与观看租约。审计记录访问、点名、音量、设备变更及采样用途，不记录凭据和整段课堂原始音视频。

删除班级时扩展现有分阶段清理：撤销终端凭据、停止媒体、终止未执行命令、清理临时采样，再删除设备及业务记录。解绑终端不删除班级 Agent、记忆或其他 Channels。

## 9. 分阶段实施

| 阶段 | 交付 | 验收重点 |
| --- | --- | --- |
| 0. 现场验证 | Windows 设备自动检测、摄像头预览、麦克风试听；必要时验证网络摄像头协议，检查显示屏/音箱及服务器网络 | 确认现有设备可读、出网可用、低配电脑负载可接受 |
| 1. Windows 托盘与点名广播 | 安装包、登录自启、配对心跳、网页三段式/自定义句子、单选多选、全文显示和播报、音量 | 显示与播报文本一致；不写考勤；声音与音量正确；退出行为正常 |
| 2. 网页实时监控 | 网页管理每班唯一摄像头、Windows 采集/网络流适配、视频和按需音频、观看鉴权 | 并发更换不产生双连接；弱网恢复、跨班拒绝、离页停流、资源占用 |
| 3. Channels 联动 | Agent 点名/音量提案、终端回执、状态查询及监控入口 | 网页 Chat 与微信可用，不绕过确认、不虚报完成 |
| 4. 概况与完善 | 按需 AI 概况、短时缓存清理、读音校正、受控安装更新 | 时间与不确定性清晰、模型用量有界、失败不影响基本功能 |

推荐优先阶段 0–1，再推进监控和 Channels。只有摄像头、硬件、出网验证完成后再估算工期；当前开发机不能替代真实 Windows 的显示、声卡、TTS 和自启验收。

## 10. 验收清单

- 重启并登录 Windows 后自动进入托盘，不抢占课件窗口；关闭设置回托盘，点击退出能正常结束。
- 三段式正确组合称谓、时间与谓词；多选合并/逐人结果正确；自定义句子不被强制套模板；长句完整显示。
- 网页预览、提案、终端显示与播报使用同一冻结文本，学生、顺序及目标终端一致；重试不重复播报。
- “下课后来办公室”默认立即播报通知，不被误当作定时指令；广播不会新增考勤、值日任务或完成记录。
- 断网、终端退出、锁屏、注销、声卡变化和显示屏断开都有真实状态，不把接收成功当作执行成功。
- 显示结束恢复原课堂界面；临时音量恢复不覆盖教师手动更改。
- 摄像头视频与音轨真实可用，缺少麦克风或不支持协议时明确提示；低配电脑优先转发而非重编码。
- 摄像头连接与更换只能从网页发起；每班最多一个，前后端和数据库共同保证；并发请求和失败重试不启用双连接，旧媒体会话及时撤销。
- 多个观看者共享上行，彼此关闭不干扰；音轨权限在媒体层执行；最后一个观看者离开后停流。
- 撤销终端/观看权限后既有连接失效；跨班访问、伪造命令和猜测播放地址均被拒绝。
- 实测 CPU、内存、带宽、稳定性和画面延迟，过载可降码率；延迟初始目标约 1–3 秒，不能在现场验证前承诺。
- 网页点名、音量和监控等确定性能力不依赖 OpenClaw 在线；自然语言和 AI 概况单独报告不可用。
- 部署、备份、恢复、媒体组件维护及班级删除有文档和回归测试。

## 11. 尚待确认的实施参数

1. 先由 Windows 设备检测确认画面与声音是否可直接读取；只有系统接口不可用时，再补充网络摄像头型号、协议或厂商接口资料。
2. Windows 版本、CPU/内存、教室屏幕连接方式、扬声器和中文语音是否可用。
3. 服务器是否能到达校内摄像头，公网/校内服务器配置、带宽及学校出网限制。
4. 监控是否需要在教室电脑关闭时继续；如果需要，要安排独立网络接入。
5. 是否只需要实时查看，还是另需录像回放；学校确定的采集时段和音频范围。

点名方式、托盘行为及优先复用掌上看家正在使用的音视频设备已经确认；具体接口由检测结果决定，不要求用户提前识别硬件型号。
