# ClassClaw Channels

ClassClaw Channels 是班级 Agent 的统一对话渠道入口，包含内置的网页 Chat 和外部渠道。网页 Chat 默认启用、无需额外绑定；微信是第一个已开放的外部渠道。后续通过 OpenClaw Channels 和各渠道兼容层逐步接入其他平台，并在网页开放同一 Agent 的多个外部渠道绑定。

## 当前已开放

- 班主任在“账户设置 → ClassClaw Channels”管理连接；建班完成页和管理员的 Agent 面板使用同一入口。
- 微信卡片保留扫码、二维码刷新、数字验证码及重新绑定能力。打开入口不会自动生成二维码或替换已有登录尝试。
- 网页 Chat 卡片显示“默认启用”，班主任可直接进入对话，无需扫码或绑定账号；该状态表示功能已启用，不代表 Gateway 实时在线。管理员仅查看该渠道状态，不通过班主任对话链接进入其他班级。
- 网页 Chat 与微信连接到同一班级 Agent，共用模型、已确认记忆和业务权限。网页对话不要求先连接微信，微信绑定开关不影响网页 Chat。
- 当前已支持网页 Chat 与一个微信账号同时使用。业务库仍将微信账号保存在 `class_agent_bindings`，多个外部账号绑定尚未开放；内置网页 Chat 不占用微信账号字段，不需要新增登录凭据或虚构绑定记录。

## 接入结构

```text
网页 Chat（内置渠道）
  → 班级归属校验 / Chat API
  → OpenClaw Responses / SSE
  → 本班 Agent

网页 ClassClaw Channels
  → 班级归属校验 / 渠道绑定服务
  → Gateway 鉴权的渠道兼容层
  → OpenClaw Channels / 对应渠道插件

外部渠道消息
  → OpenClaw (channel, accountId) 路由
  → 本班 Agent
  → ClassClaw 受限工具 / 记忆 / 预览确认
```

网页 Chat 沿用现有 Chat API、Responses/SSE 和用户/班级/会话隔离，作为产品层的内置 channel，不需要改为扫码适配器。外部渠道由 OpenClaw 负责连接、凭据及收发；兼容层负责补齐网页绑定所需的登录状态、验证、取消与清理能力。ClassClaw 后端负责班级归属、绑定记录和路由协调，不另建消息传输系统。

现有微信适配位于 `integrations/openclaw/openclaw-weixin-compat`，仍保留其供应商名称。其他渠道按各自协议添加兼容层，不要求全部采用二维码登录。前端统一入口位于 `web/js/classclawChannels.js`，具体微信登录仍由 `qrBindingPanel` 负责。

## 多个外部渠道绑定开放前必须完成的迁移

1. 保留每班唯一 Agent，将渠道连接拆为独立的一对多表。连接记录包含所属 Agent/班级、渠道类型、账号、状态、时间及错误；同一 `(channel_id, channel_account_id)` 不得跨班共享。用 Alembic 迁移现有微信记录，不能为每个渠道重复创建 Agent。
2. 增加受控渠道目录，区分无需绑定的内置网页 Chat 和需要账号绑定的外部渠道，按兼容层能力描述登录方式与可用动作；每个外部连接使用独立连接 ID、登录 ID 和验证 ID。后端验证动作白名单，浏览器不传任意 RPC、URL、路径或凭据。每个外部连接独立绑定、重绑、查询和解绑。
3. 网页改用连接列表，每张卡片只管理自己的轮询、二维码和验证码。离页释放视图和绑定请求，不取消聊天；一个渠道失败不能把整个 Agent 判为不可用。
4. 路由变更只处理目标连接。当前微信重绑已保留同 Agent 的其他渠道路由；开放同一渠道多个账号前，还须将“替换本 Agent 的该渠道”收窄为“替换该连接的旧账号路由”。已有路由归属冲突必须拒绝，不能抢占其他班级账号。
5. 将删除、初始化、重试及凭据清理改为遍历全部连接，保留分阶段恢复和共享资源检查。解绑一个连接不删除 Agent，也不影响其他渠道；删除班级须清理所有渠道的活动登录、凭据、路由及连接记录。
6. 明确提醒的目标连接和消息去重范围。当前微信投递行为继续沿用；多连接开放前必须增加连接级目标，防止同一提醒在所有渠道重复发送。分析幂等键须区分渠道、账号和外部消息 ID。

各渠道仍使用同一套 `classclaw_analyze_interaction → WriteProposal → 用户确认 → 原子执行`。渠道适配不得绕过班级隔离或写入复核。记忆按班级共享，网页对话按用户/班级/会话隔离，外部对话与登录状态按连接隔离。

## 验收要求

新渠道开放前须验证：双渠道可并行绑定；重绑/解绑只影响目标连接；账号不能跨班抢占；登录结果不能串用；渠道开关互不影响；离页清理不取消聊天；班级删除覆盖所有连接并可恢复失败阶段；提醒不重复投递。能力未完成前，不在网页展示可用的绑定按钮。
