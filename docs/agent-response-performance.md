# 智能体响应速度检查（2026-09-13）

## 实际耗时

从本机 Gateway 日志和会话的时间、工具名、用量元数据拆分耗时，未复制消息原文、学生资料、账号标识或凭据。这些是现有对话的少量样本，不是固定性能指标，也不是修改后的 A/B 测试。

| 场景 | 首次模型生成 | 工具处理 | 最后模型生成 | 整轮 |
| --- | ---: | ---: | ---: | ---: |
| 微信普通问答 | 4.50 秒 | 无 | 无 | 4.50 秒 |
| 微信单条写入预览 | 9.26 秒 | 7.67 秒 | 2.76 秒 | 19.70 秒 |
| 网页批量资料预览 | 19.32 秒 | 28.72 秒 | 6.69 秒 | 54.74 秒 |

“整轮”从 Agent 接收用户消息到最终回复生成，不包括绑定后的监听等待和渠道发送。微信单条预览从渠道收到消息到成功发送约 21 秒，其中结构化提取本身约 7.17 秒。批量预览的提取本身约 28.44 秒，生成约 1287 个 token；按变更值合并操作已生效，但仍要逐个输出学生 UUID。

另一个异常样本在预览过期后继续重新分析和尝试提交，共进行 7 次模型生成、6 次工具调用，耗时 62.52 秒。两次提交均被后端过期校验拒绝；大部分额外时间来自失败后的无效恢复尝试。

## 本次修复

1. **绑定后立即触发微信监听重载。** 原流程仅更新 `bindings`；当前安装的 Gateway 将该路径作为无需重载的路由变更。新账号直到后台健康检查才启动，本次从绑定完成到监听启动相隔约 133 秒。现在将班级路由和腾讯插件的 `channels.openclaw-weixin.channelConfigUpdatedAt` 一起写入同一次配置补丁，保留其他渠道和账号设置。网络错误、账号失效或渠道自身启动失败仍可能影响收发。
2. **阻止失败后的重新分析和替换写入。** 单条和批量提交失败统一返回 `isError`、原错误码、`retryable=false` 与结束本轮的指令。回合守卫在提交失败后同时拒绝新的分析、重建预览和再次提交；取消仍允许，新用户回合仍可正常处理。模型可能继续提出被拒绝的工具调用，不能据此承诺固定的失败响应时限。
3. **守卫跨插件实例共享。** 嵌套提取会加载插件，`before_tool_call` 和 `after_tool_call` 可能落到不同注册实例。改为进程内共享回合状态，以 Agent、会话和 run ID 隔离，保存有时效的计数及参数哈希，不保存消息原文；避免注册新实例后丢失“本轮已分析/已失败”的状态。
4. **减少工具前自述。** 班级默认工作区和 Skill 要求直接调用必要工具，在工具完成后给出简短预览、结果或澄清；同时合并工作区中的重复说明。保留管理员自定义文件、模型选择、思考档位和全部复核规则。

## 后续值得评估的优化

- **提取阶段使用短学生引用。** 每次请求由后端生成短引用并映射到本班真实 UUID，提取完成后仅在学生标识字段恢复 UUID，再走原有身份、Schema 和 proposal 校验。可减少批量任务中反复生成长 UUID 的开销，但必须测试未知引用、跨班引用、同名、批量范围和嵌套座位/事件结构。本次仅提出方案，未修改协议。
- **评估更低延迟的模型。** 当前班级和提取器使用同一模型，微信本次会话已经关闭思考。更换模型应同时比较响应时间和实际提取质量，并读取 Gateway 提供的能力；不能只根据耗时自动替换模型或静默降低用户选择的思考档位。

当前 SQLite 校验与实际提交不是主要瓶颈。继续增加数据库缓存、缩短 HTTP 超时或绕过预览确认不能解决这些样本中的主要等待。网页已有 SSE；微信完整发送与模型生成耗时应分开评估。
